# frpc-multi 服务器分类与大规模数据交互改造计划书

更新日期：2026-10-31。状态：实施中；本地归属地增补的实现与验收见本轮工作记录。

需求依据：本会话服务器分类与性能改造计划，以及用户随后明确的容量、国内主备测试节点、桌面范围与子 Agent 要求。本文件完整替代本轮会话中早先的“1 万资产、多来源比较、手机验收、主 Agent 单独执行”版本；之前已交付的前端改造记录保留为历史证据。

## 一、目标与规模边界

服务器库一条资产代表一个规范化 IP，测试端口固定为 7000。同一 IP 不因执行节点不同而创建多条资产。

| 数据层次 | 规模与处理方式 |
| --- | --- |
| 网段扫描输入 | 千万级 IP 为常见输入；按网段和游标流式生成，分块调度，采用有界队列、背压与受控并发 |
| 首轮失败目标 | 不逐 IP 写入资产、发现结果、测试历史或持久化任务明细；仅保留分块进度、汇总计数和有上限的任务诊断 |
| 首轮通过目标 | 批量持久化为发现候选；继续保持手动导入服务器库，发现与资产职责分开 |
| 入库 IP | 前期按 10 万级验收，按 100 万级设计并执行压力测试；发现候选与资产分别测量，混合场景也须覆盖 |
| 历史结果 | 独立于 IP 数量计算；容量测试至少覆盖每个 IP 三个测试项目各三轮结果，不能用单一的小历史表证明容量达标 |

“首轮通过”沿用现有首轮发现判定，目标服务端口统一为 7000。输入网段去重及重叠合并在网段级处理，避免为千万个目标建立内存去重集合。仅枚举显式 IPv4 目标范围。本轮沿用当前 IPv4 地址族边界，不扩展 IPv6 发现。

扫描断点保存范围、分块游标、租约与汇总状态。中断后允许重跑尚未完成的块，通过结果按 IP 幂等写入；汇总按块提交并去重，避免重跑重复累加。保留现有执行并发安全上限，性能优化不等同于提高生产扫描速率。

## 二、国内主备测试节点与统一结果

### 执行模型

- 配置一个国内主用测试节点，以及有顺序的备用节点；正常只由主用节点领取任务。
- 主备策略以稳定节点 ID 持久化：在测试节点页指定一个完整能力外部 worker 为 `primaryNodeId`；其余完整能力外部节点全部按顺序作为备用，Console 固定追加在最后。旧版 route-only 节点不进入主备池；离线节点保留顺序，运行时仅选择在线且满足代次协议的节点。
- 初始策略不按名称猜测；旧选优配置中的外部完整能力节点可作为 UI 建议项，需在测试节点页明确保存主备顺序。角色变更只影响之后分配的任务，不重绑运行中任务。
- 备用节点用于故障接替，不对同一目标同时执行多来源测量。取消日常任务创建中的多节点分发、服务器库结果来源切换与跨节点比较入口。
- 使用现有租约机制判断失联；失联任务在租约到期后才可转交备用节点。每次接替增加执行代次，旧代次回报不覆盖当前任务状态或正式结果。
- 任务执行代次 `generation` 从 0 开始，仅在执行节点转移时递增；每次领取仍另发 `attemptId`。新 worker 在心跳、进度和报告中回传 generation；为旧 worker 保留 generation=0 的兼容默认，generation 大于 0 时必须精确匹配。
- Worker 心跳额外声明 `task-generation-v1` 协议能力。旧 worker 可继续执行未转移的 generation=0 主用任务，但调度器只把任务转交给已声明该能力的备用 worker；备用尚未升级时保持排队，并在测试节点管理页标明待升级。
- 新任务创建时把当时已保存的主备 ID 顺序快照进 job；任务后续接替只沿该快照向后移动，不因全局策略修改而换链或回切。节点最后在线时间只由 heartbeat 更新，claim 轮询不延长在线状态；generation>0 的任务在 claim 发放时再次校验 worker 当前声明 `task-generation-v1`。
- 运行中任务仅在租约过期且当前 owner 心跳超过 30 秒未更新时转交；尚未领取的 pending 任务在 owner 离线时可转交。按主用之后的备用顺序选择首个在线且能力合适的节点。无在线备用时保持 pending 并显示等待原因，不消耗领取重试次数；一旦转到备用节点，本批次剩余阶段不抢回主用节点。
- generation、owner、attemptId 校验与每次结果/进度写入在同一事务内完成；旧 owner/attempt/generation 的进度、报告、阶段推进和发现命中一律拒绝。基础设施错误在节点在线时按现有最多三次领取策略重试；目标测试失败仍是正式结果。
- 每次实际 owner 转移在同一事务插入 `probe_task_transfers` 记录，包含 task/job、原节点、新节点、generation、原因和时间；这些不可变记录用于测试节点接替历史。
- 已完成任务保持完成；只重派未完成任务，并遵守路由、穿透、速率阶段依赖。旧节点恢复后保持待命，不抢占正在执行的备用任务；恢复主用只影响后续新任务。
- 无可用备用节点时任务保持等待并说明原因。节点失联记为执行异常，不写成目标 IP 测试失败。

### 展示与存储

- 每个 IP、每个测试项目展示统一的最新已接受结果。最新的目标测试失败也是正式结果，不回退显示旧成功结果。
- 历史保留实际执行节点、任务、执行代次与时间，用于追溯；日常列表无需选择来源。
- `probe_results` 继续作为不可变历史事实；新增按规范 IPv4、固定端口 7000 和测试项目唯一的当前投影，记录其 canonical result ID 与实际执行者来源。迁移仅以已明确配置的主节点结果初始化，未配置时保持投影未初始化，不从其他节点补齐。
- 当前投影仅由 generation/attempt/owner 校验通过的托管任务报告更新；主用和接替备用都写入相同资产槽位，失败结果覆盖旧成功。主备策略后续修改不重置已有投影，只影响新任务和之后接受的测量。
- 列表缓存、保存视图和筛选统计移除来源维度。测试节点管理展示主用、备用顺序、在线状态和接替记录。
- 域名选优读取同一统一结果，沿用现有评分、健康检查和 DNS 同步规则；移除日常全局选优来源选择。独立的主控健康检查继续保留。
- 迁移时以迁移前选定的国内测试来源结果作为初始统一结果，其他来源只保留历史，不直接混合选优。若既有配置未唯一确定国内主用节点，迁移预检列出候选，配置确认后才切换统一结果。

## 三、分类、筛选与批量管理

### 分类职责

| 机制 | 用途 | 规则 |
| --- | --- | --- |
| 业务分组 | 生产入口、备用资源、项目专用等人工业务用途 | 可选；每个 IP 最多一个分组，允许清空为未分组 |
| 自动标签 | IPinfo Lite 本地数据库识别的国家/地区、ASN；详情显示所属组织 | 系统生成且只读，按 IP 和数据库版本复用，可筛选 |
| 人工标签 | 待观察、暂不使用等补充属性 | 多值；沿用已有分类，自动刷新保留人工标签 |
| 测量条件 | 穿透、路由、速度、测试状态及测量时间 | 各项目独立展示；允许穿透通过而测速失败，状态不改变业务分组 |
| 保存视图 | 复用筛选、排序与列配置 | Console 共享；不改变资产归属或域名候选池 |
| 域名候选集合 | 指定域名参与选优的服务器 | 按服务器稳定 ID 独立维护，与业务分组、标签、测试状态分别管理 |

历史自由标签迁入“其他”。类似 CN2 的人工标签标明其人工属性，不自动转换成测量事实。

国家/地区与 ASN 使用自动标签筛选；未测试、测试中、通过、失败和过期由正式测量与运行任务表达，不要求人工维护相同含义的分组。保存视图可组合出“香港可用”“生产异常”“待复测”。保留既有地区/状态分组，不自动清理或迁移用户数据。

### 桌面操作布局

- 左侧展示全部、未分组、可搜索的业务分组和保存视图；右侧为筛选、选择摘要及分页列表。
- 基础筛选包括 IP 搜索、业务分组和穿透状态；高级筛选包括多标签、路由、上下行速度和测量时间。
- 多个分组取并集；包含标签支持全部/任意匹配，并支持排除标签；不同筛选维度取交集。
- 支持未分组、未标记、未测试、失败和过期条件。缺失结果不作为零速度参与范围比较；过期默认 24 小时，可修改并保存。
- 条件条支持逐项移除、清空与保存。保存视图不保存勾选项和页码；筛选、排序、游标及视图标识进入 URL，支持刷新和前进后退。
- 标签选择器搜索后分页返回候选及计数，替代全量标签云。计数根据其他筛选条件计算，排除自身维度；管理页总数始终使用全库统计，并明确标注口径。
- 列表默认展示 IP、分组、少量标签、关键测量结果与最新测量时间；详情按需加载历史和路由跳点。

### 管理与批量操作

- 分组使用稳定 ID，仅用于业务组织与筛选；移动或改名不改变域名候选成员。删除前检查现存资产、发现结果及遗留引用。
- 域名成员沿用 2026-10-30 域名候选池方案独立维护。旧 group API 仅生成一次性候选快照；业务分组、标签和测试状态更新不隐式增删成员。资产删除沿用已有成员级联处理。
- 改名、移动、删除、标签合并等写入操作记录；人工标签的替换、移除及旧字符串接口均保留系统自动标签。
- 标签支持分类、改名、合并；批量动作分为添加、移除和替换全部，替换明确提示覆盖范围。
- 选择区分当前页、跨页手动选择、显式选择全部匹配 IP；筛选变化不静默扩大既有选择。
- 全匹配选择由服务端物化固定 ID 集合并返回短期凭证，浏览器只保存凭证、数量和进度。大集合采用后台分批生成，不在 HTTP 请求或浏览器内展开百万 ID。
- 凭证绑定账号与筛选快照；使用前核对现存目标，新增匹配目标不自动进入。创建测试时继续展示目标数量与固定端口，并以明确提交动作执行。
- 批量修改、删除和测试创建采用幂等提交及分批处理，返回进度与分页失败明细；只重试失败项。选择凭证默认 24 小时过期，执行中的任务持有独立目标快照直至完成。

## 四、查询与前端性能

### 请求与渲染

- 将服务器库从大型 Probe 页面独立，列表、统计、详情各自按需加载。统一查询层，消除首次进入重复请求；同查询同一时间最多一个请求。
- 搜索防抖 300ms，Enter 立即查询；URL 与输入状态双向同步。缓存按完整筛选和排序区分，限制缓存页数，避免无限占用内存。
- 请求取消、响应代次校验及卸载清理统一处理。隐藏页面停止轮询，恢复可见后刷新。
- 页面有相关运行任务时每 10 秒刷新，空闲时每 60 秒；统计单独缓存最长 60 秒，分类修改后立即失效。统计独立加载，不阻塞列表。
- 切换条件时保留上一结果并标注加载中，暂时禁用旧结果批量操作；失败保留数据并展示最后成功时间，避免伪装为零。
- 默认每页 50 条，允许 25/50/100/200 条；行级更新避免勾选重绘全部组件。编辑和详情按需加载，不展开历史全量数据。
- 新大规模列表采用稳定排序与游标分页，支持下一页、上一页和按 IP 定位；总数单独返回并标注计算状态，不依赖深 OFFSET 页码跳转。旧分页接口保留兼容。

### 数据库访问

- IP 规范化与排序字段持久化，避免每次查询解析全库 IP。标签使用字典表和关联表，双向索引替代逗号字符串 LIKE。
- 资产属性查询先过滤分页，再读取本页测量摘要；分类统计不构造无关的测试结果投影。
- 为统一结果维护可重建的当前结果投影，按 IP、项目唯一；只由正式结果接受事务更新。历史是事实来源，投影不单独接受业务写入。
- 当前投影包含结果引用、状态、速度及测量时间，建立与实际筛选和排序对应的索引；避免每个请求扫描历史或创建全库临时结果表。
- 筛选统计执行 SQL 聚合，按数据修订号及筛选缓存；标签候选分页返回。大集合快照和批量写入采用短事务，避免长写锁阻塞读取。
- 验证 SQLite 的读写争用、WAL 增长及查询计划。此轮先优化现有数据库；若百万级压力测试未达到发布门槛，记录瓶颈并完成针对性改造后再发布，不宣称未经验证的容量支持。

## 五、接口、固定端口与迁移

### 接口变化

- 主备策略存于现有 `probe_settings` 的单一 JSON key `probe_execution_policy`，不以节点名作身份。`GET /api/probe/nodes/execution-policy` 返回 `configured`、`primaryNodeId`、有序 `backupNodeIds` 和仅供 UI 提示的 `suggestedPrimaryNodeId`；`PUT` 接受主节点及备用 ID 顺序。建议值只从旧域名选优来源推导，不自动保存。
- 新增分页只读接口 `GET /api/probe/nodes/failovers`，支持节点、时间筛选，返回 job/task、原节点、新节点、generation、原因和发生时间；删除节点不清除转移记录。
- 策略写入要求一个有效外部主节点，具备 discover/route/connectivity/speed 能力；其余符合要求的外部 worker 自动补入备用序列，Console 固定最后。备用唯一且不得包含主节点。离线状态不阻止保存；保存策略不重绑在途任务。各业务页移除节点选择、节点筛选和来源对比，历史仍可只读展示实际执行者。
- 服务器查询新增多分组、标签包含/排除、测量条件和游标；返回 items、nextCursor、hasMore，匹配总数可独立查询。
- 保留旧 page/pageSize 接口，兼容原 items、page、pageSize、total 格式；新旧接口共用筛选解释器。
- 新增分页筛选候选、标签管理、共享保存视图、选择快照与批量操作进度接口。
- 新任务由服务端主备策略分配；客户端不指定并行执行节点。旧客户端显式多节点提交返回明确升级提示，避免继续产生多来源任务。
- 新版创建任务省略 `nodeIds`，服务端读取已保存的主用 ID 并只创建一份逻辑任务；未配置策略时返回 400 并提示先配置测试节点主备策略。兼容请求若仍携带 `nodeIds`，只接受唯一且等于当前主用的 ID；多节点或指定非主用节点均返回 400。
- 结果历史保留执行节点用于追踪，新日常列表接口不要求 nodeId。节点协议沿用可兼容部分，租约代次能力在接替启用前核验。

### 固定端口

- 新增、导入和测试均按 IP 标识；界面显示固定 7000，不提供测试端口编辑。
- IPv4:7000 规范化为 IPv4 地址；其他显式端口逐行报错。IPv6 发现不在本轮范围。
- 服务端校验新任务端口，原始历史保留端口，统一当前结果只接受 7000。
- frpc 实例配置的端口属于独立业务，不随本次测试端口约束修改。

### 迁移与兼容

迁移前检查规范化重复 IP、非 7000 资产、域名形式资产、分组引用、现有来源与主备节点能力。冲突生成清单并暂停相应切换，不静默合并或丢弃。

分组名和自由标签通过一次性迁移映射为稳定 ID；旧接口只经兼容层访问同一事实数据，不建立双写所有者。历史保留完整执行来源，当前结果按已确认的国内主用来源初始化。发现候选手动导入资产的规则保持。

## 六、执行安排

允许子 Agent，按用户要求使用 GPT-6 Luna、高思考级别。主 Agent 先确定接口、迁移和主备执行契约，再分配无重叠职责：

1. 主 Agent：基线测量、契约与迁移顺序；协调集成、生产发布和回滚。
2. 后端子 Agent：有界发现调度、主备接替、统一结果投影及分类查询；内部按依赖顺序实施。
3. 前端子 Agent：基于锁定契约完成独立服务器库、分类筛选、视图与批量状态；先用契约样例验证。
4. 验证子 Agent：隔离数据集、故障注入、性能与浏览器回归；不同时修改实现 Agent 所属文件。

按“基线与契约 → 数据与兼容接口 → 主备与统一结果 → 分类界面与批量处理 → 综合验收与发布”形成可验证提交。前后端契约调整由主 Agent 同步，避免各自推断。

## 七、验收与发布门槛

### 功能与一致性

- 千万级输入在内存有界条件下运行；首轮失败不产生逐 IP 持久化记录。通过候选、断点恢复、块重跑与汇总去重准确。
- 规范化 IPv4 唯一，所有新测试使用 7000；裸 IPv4、自带 7000 和错误端口覆盖。
- 主用故障、备用接替、无备用、旧回报迟到、主用恢复均覆盖；同一任务最多一个有效执行代次，已完成目标不重复分发。
- 最新失败与未测试正确显示；备用接替结果纳入统一展示和域名选优，历史仍可追踪执行者。
- 分组、标签组合、保存视图、URL 恢复、游标边界和跨页选择一致；分组、自动标签和测试状态变化不改变域名候选集合。
- 百万匹配目标不传输全量 ID 到浏览器；快照生成期间的数据变化、过期、目标删除、部分失败和重复提交均有明确结果。

### 性能

隔离环境分别建立 10 万、100 万入库 IP 数据集，覆盖发现候选和资产查询；至少三项目各三轮历史，并覆盖标签偏斜、高低选择性、冷暖缓存及持续写入。记录硬件、数据库大小、索引、查询计划、P50/P95 与峰值内存。

| 指标 | 10 万级发布目标 | 100 万级容量目标 |
| --- | --- | --- |
| 50 条列表，5 个并发读取，含持续写入 | 服务端 P95 ≤ 300ms | 服务端 P95 ≤ 800ms |
| 复杂标签与测量组合筛选 | P95 ≤ 500ms | P95 ≤ 1.5s |
| 筛选候选计数及精确总数 | P95 ≤ 1s，独立加载 | P95 ≤ 3s，独立加载 |
| 勾选、打开筛选面板 | 桌面浏览器 P95 ≤ 100ms | 同左，随当前页大小而非总量增长 |
| 千万级扫描输入 | 无全量目标数组、无失败逐项持久化 | 队列、并发与内存上限保持配置有界 |

以上是验收目标，不是已测结论。深游标翻页需验证耗时不随已翻页数线性增长；扫描吞吐记录实际网络和并发条件，不以生产公网扫描速度作为 UI 验收标准。

使用既有后端测试、Vitest、Playwright 和隔离压力工具。桌面验收覆盖 1280、1440px、浅深色主题、键盘与弹窗焦点；手机专项适配与 390px 验收移出本轮范围。

发布到 23.19.228.204:8081 前备份数据库、保留旧镜像并验证恢复流程。先完成数据库与节点协议兼容，再切换新 UI 和主备策略；旧在途任务先结束或明确停止后再切换，避免混用调度模型。生产只用专用小目标验证接替和写入，千万/百万级压力测试在隔离环境进行。回滚涉及数据库迁移时必须恢复对应备份，不仅回退镜像。

完成标准：用户通过可选业务分组管理用途，通过自动地域/ASN 标签和统一测量结果筛选 IP；域名候选独立管理，主备切换不增加日常操作负担，扫描输入和入库规模增长不会导致浏览器全量加载或失去响应。

## 八、本地 IP 自动归属地识别（2026-10-30 增补）

### 数据源与识别范围

- 固定采用 IPinfo Lite MMDB，由 Console 查询国家/地区、ASN 和所属组织；仅支持当前 IPv4 范围，不接入逐 IP 在线 API。
- 发现命中及已入库资产的正式测试结果（包括目标失败）在事实保存事务内登记待处理 IP。过期执行节点、取消、基础设施异常不触发识别。
- 按规范化 IP 保存唯一归属地事实及版本、时间、处理状态。跨测试节点、端口及重测复用；发现候选导入资产时沿用已有结果。纯手工导入且未测试、无发现记录的 IP 暂不主动查询。
- 持久化队列与历史回填采用每批 250 条和短事务，支持重启续跑；首轮扫描失败不建立逐 IP 地理记录。

### 标签、接口与维护

- 系统分类为“自动归属地”和“自动 ASN”；以国家代码、ASN 编号为稳定标签身份，组织名称保留在事实及详情展示。事实和生成标签在同一事务更新。
- 自动分类/标签返回 `source=geoip`、`readOnly=true`，人工分类为 `manual`。人工增删、替换、改名、移动和合并受服务端保护，旧标签字符串接口也保留系统关联。
- 列表/详情返回 `geo`：状态、国家/地区代码与名称、ASN/组织、来源、数据版本、识别时间及待刷新标志。发现页按 IP 关联同一事实。
- 资产返回独立的 `manualLabels`，按标签来源提供人工编辑初值，保留与自动国家代码或 ASN 同名的人工属性。
- 数据文件默认 `/data/geoip/ipinfo_lite.mmdb`；支持挂载现成文件，或配置服务端 `IPINFO_TOKEN` 首次下载并每 24 小时检查更新。Token 不返回浏览器或日志。
- 下载到临时文件，校验格式和字段后原子替换；每批查询固定使用同一已验证快照。更新后分批刷新仍被候选或资产引用的 IP。
- 缺库保留队列；更新失败保留有效旧库并显示错误和数据年龄。非公网单独标记，数据缺失显示未知。`GEOIP_ENABLED=false` 暂停处理，原有测试、业务分组、人工标签和域名选优继续运行。
- 鉴权接口：`GET /api/geoip/status`、异步 `POST /api/geoip/update`、`POST /api/geoip/refresh`。系统页展示版本、时间、进度与维护入口，保留 IPinfo 署名及 CC BY-SA 4.0 数据许可。

### 验收与上线顺序

- 先完成兼容迁移及库校验，再后台补齐已有发现候选和已正式测试的资产；不清理既有分组或修改用户视图。
- 验证命中、测试成功/失败、幂等、旧报告拒绝、标签保护、组清空、候选集合隔离，以及缺库/坏文件/下载中断/更新并发/重启恢复。
- 10 万及 100 万不同 IP 隔离测试记录补标耗时、内存、SQLite 写锁、列表/筛选/统计 P50/P95；沿用本计划性能门槛，逐 IP 外部 HTTP 请求数为零。小型公共样例用于真实 MMDB 解码回归；容量数据使用显式标注的合成归属地，不将样例表现描述为全球数据准确率。
