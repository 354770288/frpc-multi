## 切片与通过条件

1. 兼容接口：任务、任务详情、历史及操作记录服务端分页和筛选；任务显式目标范围；旧接口返回保持。验证后端回归及真实规模的只读查询。
2. 导航与主流程：独立发现、资产、任务、结果、测试节点、域名、实例和部署节点入口；旧地址跳转；新测试必须核对目标、执行节点和影响后提交。验证刷新/返回/来源切换及空目标拒绝。
3. 域名与实例：域名先状态后设置，未知健康为未知；实例创建三步，保留端点端口；配置保存与重启分开，草稿离开保护，结构化仅接受无损往返的 TOML。验证真实结果和失败恢复。
4. 质量：统一组件弹窗与错误/空/陈旧状态，URL 承载列表查询，桌面与 390px 手机宽度验收。前端构建、Vitest、Playwright 与后端全测通过。
5. 上线：先做线上数据库备份与旧镜像回滚标记；兼容接口与前端同镜像发布；使用登录后的只读路径、专用测试目标和现有业务状态验收；确认服务稳定后同步 GitHub 与交接记录。

## 所有者与边界

- `webui/backend/app/probe/jobs.py` 与 `control/audit_store.py` 负责有索引的分页投影；规范化结果和节点租约所有者保持不变。
- 前端路由、页面和查询状态负责呈现来源与操作范围；任务创建仍调用现有 `/api/probe/jobs`，DNS 同步仍调用既有域名接口。
- 旧 `/probe`、`/create` 与实例详情链接兼容。用户资产、业务 DNS、管理 Agent 与测试节点身份不迁移。
- 未知数据单独呈现；任务历史总数与筛选总数不可混用。后台失败保留已成功数据并标记陈旧。

## 发布验收

本地用假数据覆盖：旧链接、明确目标、无自动提交、双节点、分页超过200条、配置草稿和扩展 TOML、未知健康状态、手机宽度。生产使用只读状态与专用目标核验；记录镜像代码版本、管理实例状态与回滚点。
