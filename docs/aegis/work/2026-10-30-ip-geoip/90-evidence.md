## 边界与实现

- Console 的 app/geoip 维护唯一归属地事实、持久化待处理状态、MMDB 下载与不可变字节快照；数据和版本散列来源于同一份字节。
- 发现命中及已接受的正式测试结果在原事务登记 IP；资产及发现源复用规范 IPv4 身份，兼容既有 IPv4:7000 资产。
- 自动标签是事实投影；人工修改保留它们，同名人工标签通过 manualLabels/source 身份区分。业务分组可留空，域名候选成员独立。
- 无逐 IP HTTP；仅整库下载允许网络访问。公开 MMDB 小样例来自 IPinfo，保留 CC BY-SA 4.0 署名和许可。

- 合成正向数据覆盖 20 个国家代码、200 个 ASN，每个 IP 都生成两条事实标签与两条资产关联；真实 MMDB 解码另用已固定的公共小样例测试。
- 查询并发为五个读取线程及一个持续 250-IP 归属地刷新写入线程；记录 P50/P95、SQL 计划、DB/WAL、RSS、HTTP 尝试及完整性。

- 测量为本机 Apple M4 / 16 GiB / Python 3.14 / SQLite 3.51 的隔离合成数据，不代表生产硬件性能或真实全球定位准确率。

## 最终容量结果

报告：capacity-100000.json、capacity-1000000.json。每级数据完整性 `quick_check=ok`；分别有 10 万/100 万条 ready 事实、20 万/200 万条事实标签和资产标签关联。发现记录补入真实默认路由状态标签后复测。

| 服务端操作 P95 | 10 万 IP | 100 万 IP | 对应门槛 |
| --- | --- | --- | --- |
| IP 列表（含归属地与人工标签） | 36.5ms | 38.9ms | 300ms / 800ms |
| 复杂标签与测量组合筛选 | 53.3ms | 286.2ms | 500ms / 1.5s |
| 最重分类统计 | 222.8ms | 2.728s | 1s / 3s |
| 发现标签、分组与入库统计 | 56.3ms | 1.382s | 1s / 3s |

- 五个读取线程与一个持续后台写入线程，每批 250 IP；最终生产与基准间隔均为 100ms，两个数据级别全部门槛通过。
- 原先无间隔饱和写入及 20ms 节奏的超时结果在报告中保留；不将这些极限负载下的统计延迟宣称为达标。100ms 让步是实际 GeoService 调整，门槛未放宽。
- SQL 修复包括先分页后解码、索引驱动标签计数/筛选、排序 EXCEPT 计算未入库 IP、先聚合标签字典与发现标签字符串，避免重复逐行解码。
- 原始初始正向填充吞吐仅对应报告标注的旧源码散列；最终查询散列单独列出。最后 SELECT/调度复测复用同数据库之前的完整性与 HTTP 拦截验证；内存峰值字段保留原始采集轮次，不伪称每次复测重新采峰。
