## 产品行为

- 测试节点主动出站连接主控，支持网段发现、去程路由、穿透连通性、上下行速率以及完整流程。多选节点时，每个节点独立执行全部目标。
- 完整流程为路由、连通性、通过后测速；路由失败继续连通性。发现后可选自动路由或自动完整测试，后续阶段固定来源节点。服务器库导入保持手动。
- 资产、分组和用户标签共享；发现延迟、路由、连通性和速率按节点、目标主机、端口与时间隔离。列表、分页排序、统计、历史和比较使用相同来源。
- `console` 是稳定的内置节点标识；外部节点使用稳定 UUID。现有路由节点保留名称及 Token，未升级时提供路由能力，升级后上报实际能力和构建版本。
- 全局选择一个稳定国内节点提供 LB 排序观测，主控持续负责健康检查。测量由手动或扫描流程触发，默认有效期 24 小时，可设置 1–168 小时。
- 最新失败覆盖该类型的旧成功。指定来源缺失或过期时保留健康当前 IP；当前 IP 故障时依有效观测或健康 IP 的固定数值顺序切换。全部候选不健康时保留 DNS 并提示。A 记录只包含主机地址，测试观测仍精确匹配端口。

## 架构与运行边界

- `probe/jobs.py` 的 `ProbeJobStore` 是生产任务、租约及规范化结果的唯一所有者，数据持久化于 Console SQLite；`control/database.py` 维护 schema 与初始化。
- `probe/executor.py` 复用 `engine.py` 和 `discover.py` 的测试算法。`worker.py` 是标准库节点运行器，Console 也通过相同协议执行。节点没有实例管理 Agent 的管理权限。
- `probe/store.py` 维护资产查询与按来源读取的兼容投影：每个资产通过规范化端点索引读取最新结果，形成有索引的临时只读投影；完整历史直接读取规范化历史存储。历史原始表快照归 Console，旧路由结论来源未知。历史表继续作为兼容数据，新增任务结果以规范化结果表为准。
- `/api/probe/nodes` 管理身份与能力；`/jobs` 管理批次；`/worker/*` 通过独立 Token 领取、续租及回报。面板接口继续使用用户登录认证。旧测试及路由 HTTP 入口适配统一任务所有者。
- 默认每 10 秒心跳、120 秒租约、90 秒失去续租中止本机执行。任务与 attempt 凭证共同隔离回报，重复回报幂等，迟到回报不覆盖新 attempt。基础设施故障最多三次执行，目标失败不自动重试。
- 取消任务保留锁至执行器清理确认或租约到期；重试遵守阶段依赖，保留成功下游。相同 frps 主机的隧道测试跨节点互斥，连接测试分配不相交的实际本地端口组，节点测速排他。
- 扫描保持 10,000,000 个有效 IPv4 目标上限、区间表示及惰性遍历，以 4096 地址分块。命中先事务提交并确认，再推进后续阶段。任务详情分页，全批次按节点及阶段的计数由后端 SQL 聚合。
- systemd 安装器及共享源码包由主控提供；Debian/Ubuntu amd64/arm64 安装 Python、mtr 和固定 frpc 版本。升级保留身份、上一程序目录和旧路由服务配置，配置文件权限为 0600。可通过 FRPC_ARCHIVE 提供本地官方固定版本 frpc 归档，安装时校验二进制版本0.68.1；国内节点实测使用该路径。
